# 轻记：产品、数据与 UI 设计（v1）

## 1. 产品边界

**轻记**是面向个人、夫妻/情侣和小型家庭的日常收支记录工具。它只回答三件事：今天花了什么、这个月还剩多少、钱主要花在哪里。v1 不做资产负债、信用卡账单、报销流或复杂分账；这些能力会增加录入成本，违背“轻量、极速”的定位。

### 产品原则

1. **三秒完成一笔支出**：打开应用默认进入记一笔；金额输入获得焦点；展示最近使用的分类和付款人。
2. **一本共享账，成员实时可见**：所有流水天然归属账本，服务端按账本成员校验读写权限；本地先写入，再后台同步。
3. **只提供可行动的信息**：首页仅展示本月支出、剩余预算、最近记录和前三分类，而不是复杂财务报表。
4. **移动端单手可达**：主要操作处于屏幕下半部分，核心页面不超过两层。

## 2. 基础数据库表结构

完整 PostgreSQL DDL 位于 [`docs/sql/001_initial_schema.sql`](sql/001_initial_schema.sql)。金额均用 `bigint` 的**分**存储，防止浮点误差；业务时间用 `timestamptz` 存储，用户时区保存在用户表中。

| 表 | 关键字段 | 用途与规则 |
| --- | --- | --- |
| `app_user` | `id`、`phone/email`、`display_name`、`timezone` | 用户身份与展示信息。手机号或邮箱至少其一存在，避免把认证方案锁死。 |
| `ledger` | `id`、`owner_id`、`name`、`currency`、`monthly_budget_cents` | 一个独立个人或家庭账本。预算是月度总预算，v1 保持简单。 |
| `ledger_member` | `ledger_id`、`user_id`、`role` | 账本共享关系；复合主键保证成员不重复。角色支持 `owner/member/viewer`，可直接支撑邀请家庭成员。 |
| `category` | `ledger_id`、`entry_type`、`name`、`icon`、`color` | 收支分类。`ledger_id = NULL` 可容纳平台预置分类；有账本 ID 的为家庭自定义分类。归档而不硬删除，确保历史流水可回溯。 |
| `transaction_record` | `ledger_id`、`category_id`、`created_by`、`paid_by`、`entry_type`、`amount_cents`、`occurred_at` | 每一笔收入或支出。`created_by` 保留录入审计，`paid_by` 便于按家庭成员分析；软删除帮助多端增量同步与误删恢复。 |

### 关系与同步约束

```text
app_user 1 ── * ledger_member * ── 1 ledger
ledger   1 ── * category
ledger   1 ── * transaction_record
app_user 1 ── * transaction_record (created_by / paid_by)
category 1 ── * transaction_record
```

- 服务端所有流水查询必须先通过 `ledger_member` 限定账本，不能只根据 `transaction_record.id` 查询或修改。
- 客户端给新增流水生成 UUID；本地数据库设置 `sync_state`（`pending/synced/failed`）和 `updated_at`，网络恢复后按 `updated_at` 增量上传。冲突优先采用服务端最后写入，但对删除使用 `deleted_at` tombstone，避免旧设备“复活”已删除的记录。
- 每个账本创建时：写入 owner 的 `ledger_member` 记录，并复制一套常用分类（餐饮、交通、居家、购物、娱乐、工资、奖金）。

## 3. Mobile First UI 框架

### 底部导航：四个一级入口

| 入口 | 页面职责 | 核心内容与操作 |
| --- | --- | --- |
| **首页** | 快速了解本月家庭收支 | 本月支出、剩余预算、收入/结余、最近流水、分类 Top 3；点击卡片进入对应明细。 |
| **账单** | 浏览和检索历史记录 | 按日期分组的流水列表；顶部仅保留“本月/筛选”；左滑编辑或删除。 |
| **记一笔** | 极速录入，默认选中 | 数字键盘、支出/收入切换、最近分类、付款人、备注；保存后立即回到账单并给轻提示。 |
| **我的** | 设置和共享管理 | 当前账本切换、成员邀请与权限、分类管理、月预算、数据导出与同步状态。 |

其中“记一笔”应当是凸起的中央主按钮，而不是隐藏在二级菜单；点击后以半屏 Bottom Sheet 打开，保留用户当前上下文。分析不占用一级入口：首页的分类 Top 3、点击“本月支出”或账单筛选后的“按分类”即可进入轻量分析页。

### 页面层级与关键交互

```text
首页 ── 点击流水 ──> 流水详情/编辑
账单 ── 筛选 ──────> 月份、分类、成员（Bottom Sheet）
记一笔 ────────────> 保存（留在当前页继续记 / 返回账单）
我的 ── 当前账本 ──> 成员管理 / 邀请成员
     └─ 分类与预算 ─> 轻量设置页
```

- **默认页**：新用户没有数据时显示“记下第一笔”的空状态；有数据时显示首页。记一笔按钮始终固定在底部中间。
- **录入流程**：先金额，再选分类；分类采用 4 列图标网格，并将最近三次和常用分类置顶。付款人默认为上一次选择，家庭账本默认“共同”。
- **分析呈现**：仅提供“本月/上月”时间切换、分类排行和成员占比；每个结论配一个可点击明细，不增加难理解的财务术语。
- **共享反馈**：账单行显示付款人头像/名称；保存后本地立即可见，在后台上传。同步失败时只在“我的”显示可重试状态，避免打断记账。

## 4. v1 验收标准

1. 用户打开“记一笔”至保存一笔已有分类的支出，不超过三次必要点击（不计数字键盘输入）。
2. 账本成员新增的流水在另一成员联网后可见，且流水包含付款人。
3. 首页能在一个屏幕内读到本月支出、预算剩余和最近三笔流水。
4. 分类与成员任一维度都可以从首页/账单进入明细，且筛选状态可清楚地被看见和清除。
